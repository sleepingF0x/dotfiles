# 凭证轮换设计（因 Apifox 漏洞）

## 背景与目标
- Apifox 平台出现安全漏洞，可能暴露 SSH 私钥与 Git Personal Access Token（PAT）。
- 目标：立即阻断潜在滥用风险，并在所有相关环境中完成凭证轮换。
- 范围：个人/项目用 SSH 密钥、公私仓库 Git Token、CI/CD 与服务器依赖的同源凭证。

## 1. 紧急响应
- **责任人与时限**：安全负责人立即牵头（≤4 小时内完成撤销），各系统 owner 在 24 小时内完成资产清点。
1. **撤销 Git Token**
   - 登录 GitHub/GitLab → Settings → Developer Settings → Personal Access Tokens。
   - 删除所有与 Apifox 项目相关或近期使用的 PAT；如有 GitHub App/Deploy Key，同步撤销。
2. **禁用旧 SSH Key**
   - 在 Git 平台账号设置、所有服务器 `authorized_keys`、CI/CD Credential Store 中移除旧公钥。
   - 清理 ssh-agent 缓存（`ssh-add -D`）并重启 agent。
3. **清点受影响资产**
   - 使用统一模板记录：`唯一 ID | 系统名称 | 凭证类型 | 存放位置/路径 | 负责人 | 风险级别 | 创建时间 | 上次轮换时间 | 当前状态 | 备注`。
   - 覆盖开发设备、服务器、CI/CD、容器、脚本、密钥管理器等；清单存入共享表单/版本库，供后续轮换确认。
4. **轻量入侵排查（范围最小化）**
   - 检查 Git 平台「Security Log」过去 7 天是否存在异常 IP/设备；发现异常则将账号置于“受限”状态，并延后对应凭证回滚。
   - 服务器查看 `auth.log`/`secure` 中与疑似泄露时间匹配的 SSH 登录；如检测到失败暴力尝试，需先禁用相关账号。
   - Apifox 项目活动记录中若发现未知访问，立即移除对应成员或链接。

## 2. 新凭证生成与分发
- **责任人与时限**：各系统 owner 在 48 小时内完成新凭证部署；安全负责人 72 小时内完成总体确认。
1. **生成新的 SSH 密钥对**
   - 在可信终端使用 `ssh-keygen -t ed25519 -C "<label>"`（或 `rsa -b 4096`）。
   - 私钥设置强密码并存入受信密码管理器；仅通过安全通道分发公钥。
2. **生成新的 Git Token/其他密钥**
   - 创建最小权限 PAT（仅必要仓库与 scopes）。
   - 若 Apifox/CI 等处保存了旧 token，全量替换并限制可见成员/环境。
   - 同步更新任何脚本、容器镜像、函数服务等所需访问密钥。
3. **替换、验证与受控回滚**
   - 在所有开发机、服务器、CI 配置中更新 `.ssh/config`、环境变量、Secrets Manager 等后执行验证：
     - SSH：`ssh -i <new_key> user@host` 确认可登录。
     - Git：`GIT_SSH_COMMAND="ssh -i <new_key>" git ls-remote <repo>` 或 `git push`。
     - CI/CD：触发一次干运行或无害部署，确认凭证有效。
   - **回滚条件**：仅在业务无法中断且已确认无可疑访问记录时，且旧凭证被隔离（移除在 Git/服务器的信任列表）后，才可临时恢复旧凭证；恢复期间必须记录时间与负责人，并在 2 小时内再次尝试轮换。
   - 完整记录“凭证 → 使用位置 → 存放方式 → 验证结果/时间 → 回滚记录（若有）”，便于未来轮换。

## 非功能性要求
- 全流程完成后，应只保留新凭证，并确认旧凭证在任何平台不可用。
- 未来如需在第三方平台使用凭证，优先采用临时 token 或参数化调用，避免明文存储。
- 记录轮换完成时间，作为后续定期轮换（建议 ≤90 天）的起点。
